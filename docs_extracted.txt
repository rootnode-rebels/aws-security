Property | Detail
Severity | ≡ƒö┤ CRITICAL (UX + Cost)
Files | aws/template.yaml (Line 130), backend/security/notification_service.py
Description | The CloudWatch Alarm HighRiskRateAlarm triggers SNS when >= 3 BLOCK_SESSION events occur in a 5-minute window. Every attack simulation, test run, or login from a new device can trigger this. The notification_service.py then sends: SNS email, In-App alert, Desktop toast, and CloudWatch log ΓÇö all for EVERY single event with no deduplication or cooldown.
Risk | Alert fatigue (team ignores real alerts). SNS/SES cost spikes. Notification storms during demos.
Fix 1 | Raise alarm threshold in template.yaml from 3 to 10+ for production.
Fix 2 | Add a per-user cooldown in notification_service.py (e.g., max 1 alert/type/5 minutes).
Fix 3 | Use SNS filter policies to route only HIGH severity alerts to email.
Effort | 1-2 hours
Property | Detail
Severity | ≡ƒö┤ CRITICAL (Deployment)
File | Dockerfile (Line 27) vs docker-compose.yml (Line 10)
Description | Dockerfile sets ENV PORT=80 and EXPOSE 80, but docker-compose.yml maps port 8000:8000. This means the app inside the container starts on port 80, but Docker maps external 8000 to internal 8000 ΓÇö so no traffic reaches the app.
Risk | Container deployment fails silently. Health checks fail. App is unreachable.
Fix | Choose one port. Recommended: set PORT=8000 in Dockerfile, and keep compose as 8000:8000.
Effort | 10 minutes
