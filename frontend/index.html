🧠 Machine Learning Model & Risk Scoring Architecture

  • Haversine Geo-Velocity: Calculates great-circle flight distance \(d = 2R \arcsin(\dots)\) and velocity \(v = \frac{d}{\Delta t}\). If velocity \(> 900\text{ km/h}\), Impossible Travel is flagged (+30 to 45 pts).
  • Scikit-Learn Random Forest: Supervised classifier trained on behavioral feature vectors calculating hijacking probability (weighted 60%).
  • Scikit-Learn Isolation Forest: Unsupervised outlier isolation tree detecting multidimensional behavioral anomalies (+10 pts outlier penalty).
  • TensorFlow Deep Autoencoder: Neural network computing Mean Squared Error (MSE) reconstruction loss: \(MSE = \frac{1}{n} \sum (x_i - \hat{x}_i)^2\). Normal logins have low MSE (< 0.05); hijacked attacks exhibit high reconstruction error (> 0.12).
  • Policy Enforcement Thresholds:
    • Score < 40: LOW RISK → ALLOW
    • Score 40 – 69: MEDIUM RISK → STEP_UP_MFA
    • Score ≥ 70: HIGH / CRITICAL → BLOCK_SESSION (Attacker blocked, legitimate user alerted).

☁️ AWS Serverless Cloud Architecture Mapping

This application was architected for zero-cost serverless cloud deployment using AWS SAM (aws/template.yaml):

  • Amazon API Gateway: Validates input schemas (Pydantic), manages CORS, and routes REST endpoints.
  • AWS Lambda (AuthHandler): Executes PBKDF2 password authentication and session tokens.
  • AWS Lambda (RiskEngine): Executes Scikit-Learn and Autoencoder ML models in isolated containers.
  • Amazon CloudWatch: Aggregates custom metrics (Invocations, HighRiskDetections, BlockedHijacks) and fires metric alarms.
  • Amazon SNS: Dispatches emergency alerts and notifications to legitimate users.
  • DynamoDB / MongoDB: Encrypted persistence for users, session kill-switches, and audit trails.

🎓 Top Viva / Examiner Questions & Model Answers

Q1: How does the system detect an attacker who already has the correct username and password?

Answer: Standard authentication only verifies what the user knows (credentials). AWSSecurity implements Continuous Behavioral Authentication. Even with correct credentials, the ML Engine evaluates contextual telemetry: geographic velocity (Impossible Travel), hardware canvas fingerprint distance, IP reputation (Tor/datacenter), and circadian access hours. If these deviate from the learned baseline, the session is blocked.

Q2: What is the difference between supervised Random Forest and unsupervised Autoencoders here?

Answer: Random Forest classifies known attack vectors based on labeled threat data. The Deep Autoencoder neural network is unsupervised: it learns the reconstruction of legitimate user behavior. When novel, zero-day attack patterns occur that Random Forest may not recognize, the autoencoder fails to reconstruct them, generating a high MSE error that catches zero-day account takeovers.

Q3: How does the kill switch work across multiple devices?

Answer: Active sessions are maintained as atomic document records in MongoDB. Every authenticated request checks the session token's active status. When a user clicks "Kill Session" or "Freeze Account", the backend invalidates the token or marks the account LOCKED. The attacker's next HTTP request or live polling heartbeat is rejected with 401/403, immediately booting them out.
